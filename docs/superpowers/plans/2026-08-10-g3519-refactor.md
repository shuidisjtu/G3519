# G3519 重构实施计划:统一平台库 + 双题目应用

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把三分支(main/control/signal)重构为单仓库单 main 分支,目录结构 common(平台库)+ control(控制题应用)+ signal(信号题应用),共享代码物理一份、分叉模块内容级合并,两套 IAR 工程编译通过。

**Architecture:** 以 main(基础平台)为骨架,`git merge control/signal -s ours --no-commit` 建立历史关联(第二父提交)但不引入冲突;工作树用 `git checkout <branch> -- <path>` 组装到新目录结构,提交为 merge commit。依赖方向单向:`control/app`、`signal/app` → `common/drivers` → `common/TSP3519`(架构原则,见 spec 第 4 节)。

**Tech Stack:** git(merge -s ours + 显式组装)、IAR EWARM(iarbuild 编译验证)、sed/批量路径重写。

**Spec:** `docs/superpowers/specs/2026-08-10-g3519-refactor-design.md`(本地,已获批准)

## Global Constraints

- **架构原则 8 条**(spec 第 4 节)为宪法级约束:单向依赖、不复制 common、稳定 API 契约、清僵尸代码、记录"为什么"
- 依赖方向:`app → drivers → TSP3519`,禁止反向;common 不引用题目特有代码
- 共享模块物理一份;合并取最新最完整(表见 spec 第 6 节)
- 每阶段 `iarbuild` 编译 0 错误才进入下一阶段
- 提交遵循项目惯例:`<type>: <描述>` + `Co-Authored-By: Claude <noreply@anthropic.com>`
- `docs/superpowers/` 保持出库(.gitignore 已含),不参与重构
- 阶段 4 push main 需 `CC_PROTECT_BRANCHES=` 临时豁免(用户已授权此模式)

## 路径重写规则(.ewp/.ipcf/.eww 中)

基于 `$PROJ_DIR$`(重构后 = `control/iar/` 或 `signal/iar/`):

| 旧路径(重构前) | 新路径(重构后) |
|---|---|
| `$PROJ_DIR$\..\TSP3519\...` | `$PROJ_DIR$\..\..\common\TSP3519\...` |
| `$PROJ_DIR$\..\NUEDC2025\tsp_{isr,key,encoder,uart,uart_k230}.*` | `$PROJ_DIR$\..\..\common\NUEDC2025\...` |
| `$PROJ_DIR$\..\NUEDC2025\tsp_{motor,mpu6050,pid}.*` | `$PROJ_DIR$\..\..\common\drivers\...` |
| `$PROJ_DIR$\..\NUEDC2025\tsp_{k230,linefollow,odometer,wheel_enc}.*`(control) | `$PROJ_DIR$\..\app\...` |
| `$PROJ_DIR$\..\NUEDC2025\tsp_{cmd,fft,scope,tjc,mcp41010,ad8302}.*`(signal) | `$PROJ_DIR$\..\app\...` |
| `$PROJ_DIR$\..\NUEDC2025\tsp_{ad5933,dds,adc,uart3,uart6}.*`(signal) | `$PROJ_DIR$\..\..\common\drivers\...` |
| icf/startup/syscfg 等 iar 内部文件 | 不变(随 iar 目录整体移动) |

include 路径(编译器 IncludePath)同步按上表更新。源码内 `#include "tsp_*.h"` 依赖 include 路径,通常无需改(遇到遗漏以编译错误为准逐个补路径)。
