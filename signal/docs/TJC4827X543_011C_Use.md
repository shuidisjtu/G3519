# TJC4827X543 串口屏使用

> 适用对象：TJC4827X543_011C（X5 系列，4.3 英寸、480×272）与 MSPM0G3519。  
> 资料依据：淘晶驰资料中心的[常见问题](http://wiki2.tjc1688.com/QA/index.html#id6)、[指令集](http://wiki2.tjc1688.com/commands/index.html)、[返回数据格式](http://wiki2.tjc1688.com/return/index.html)及题目提供的型号规格书链接。网页访问日期：2026-07-27。
> 本文档合并自原 `TJC_UI_Spec.md`（最小验证工程教程，见第 6-8 节）。

## 结论先行

- **TJC 屏通过 UART3 (J4, PC6 TX / PC7 RX) 通信，双向通信已验证。** 屏 TX（约 5 V）到 MCU RX（3.3 V、非 5 V 耐受）理论上需电平转换，但实测直连可工作。
- **J4 Pin1 (5V) 带载不足（实测空载 4.7V，接屏后压降过大），TJC 屏需从其他 5V 接口独立供电。**建议电源余量 ≥1 A。
- **MCU 侧已切换到 115200 baud、8N1。** TJC 屏 HMI 工程的 `bauds` 也需设为 115200 以匹配。实际出厂工程可能已改写 `bauds`，上电后应以工程设置/联机测试为准。
- 不需要额外的硬件复位或背光脚：复位和亮度由串口指令 `rest`、`dim/dims` 控制。

## 1. 硬件接口

### 1.1 模块接口与接线

该尺寸 X5 模块通常使用 **XH2.54-4P** 主接口。其信号为 `VCC`、`GND`、`TX`、`RX`（最终以模块背面丝印为准，接线前逐一核对）。主接口不含独立背光使能脚或硬件复位脚；部分型号另有喇叭接口或扩展 IO，但不是 UART 接入必需项。

| 屏端引脚 | 功能 | 与 G3519 / J4 的连接 | 备注 |
| --- | --- | --- | --- |
| VCC | 5 V 供电输入 | **其他 5V 接口独立供电**（J4 Pin1 带载不足） | 可从 P5V_MCU 或其他 5V 排针飞线 |
| GND | 电源与信号地 | J4 Pin2 GND | 必须共地 |
| RX | 屏串口接收 | MCU PC6 / UART3 TX (J4 Pin4) | 3.3 V TX 可被 5 V TTL 屏识别 |
| TX | 屏串口发送 | MCU PC7 / UART3 RX (J4 Pin3) | X5 串口约 5 V，实测直连可工作，严格应加分压 |

### 1.2 电源与逻辑电平

- **供电：5 V。** J4 Pin1 空载约 4.7V，但带载压降过大无法驱动 TJC 屏。需从其他 5V 接口（如 P5V_MCU 或其他 5V 排针）独立供电。4.3 英寸带背光屏的启动/背光电流具有峰值，工程上建议电源能力至少留到 **1 A**，并在屏端加适当的去耦和储能电容。
- **UART：TTL，X5 系列约 5 V。**屏的 VCC 使用 5 V 与 UART 信号电平是两件独立的事。淘晶驰 FAQ 明确指出 X3/X5 系列串口电压约为 5 V；对 3.3 V MCU，只有 MCU 串口 IO 为 5 V 耐受时才可直接接收屏 TX。本板的 PC7 是普通 SDIO，不是 5 V 容限开漏 IO，理论上需进行 5V→3.3V 电平转换（推荐上臂 10kΩ、下臂 20kΩ 分压）。**实测直连可正常通信**（GPIO 内部钳位二极管吸收小电流），但长期使用建议加分压保护。
- **背光：**没有独立背光控制脚；用 `dim=<0..100>` 临时调节，`dims=<0..100>` 设置上电默认亮度。
- **复位：**没有必需的独立 RESET 接线；使用串口命令 `rest` 软件复位。

## 2. 通信协议

### 2.1 UART 参数

- 推荐首次接入：**9600、8 数据位、无校验、1 停止位（8N1）**。
- 支持波特率：2400、4800、9600、19200、38400、57600、115200、230400、256000、512000、921600。
- 可由工程的 `bauds` 设置上电默认波特率，`baud` 修改当前波特率。因此如果出厂 HMI 已配置 `bauds=115200`，实际默认值就是 115200；应先从出厂工程或联机调试确认，不能只依赖通用默认值。

### 2.2 MCU → 屏：命令帧

命令采用 ASCII 指令，**每条命令必须以 `FF FF FF` 三字节结束**。例如：

```text
t0.txt="Hello" FF FF FF
page 0 FF FF FF
add s0.id,0,128 FF FF FF
```

若启用执行状态返回（`bkcmd` 非 0），屏会回传状态帧；例如 `01 FF FF FF` 表示指令成功，`12 FF FF FF` 表示曲线控件 ID 或通道无效。

### 2.3 屏 → MCU：返回帧

各返回帧统一以 **`FF FF FF`** 结束；应使用 UART 中断 + 环形缓冲区按帧头、固定/可变长度和帧尾解析，避免把半帧或粘包当作完整消息。

| 场景 | 帧格式（十六进制） | 总长度 | 说明 |
| --- | --- | ---: | --- |
| 按键/控件事件 | `65 page_id component_id event FF FF FF` | 7 B | 勾选控件“发送键值”后产生；`event=01` 按下，`00` 弹起 |
| 当前页面 ID | `66 page_id FF FF FF` | 5 B | 查询页面时返回 |
| 触摸坐标 | `67 xH xL yH yL event FF FF FF` | 9 B | `sendxy=1` 后上报；`event=01` 按下，`00` 弹起 |
| 字符串变量 | `70 ASCII... FF FF FF` | 可变 | `get` 字符串变量时返回 |
| 数值变量 | `71 data0 data1 data2 data3 FF FF FF` | 8 B | 32 位数值，按文档规定字节序解析 |
| 启动完成 | `88 FF FF FF` | 4 B | 可用于判断屏已启动 |

### 2.4 主动上报/主动解析

- **支持。**控件事件无需 MCU 轮询：为控件勾选“发送键值”即可主动发送 `0x65` 事件。
- 触摸坐标可通过 `sendxy=1` 主动发送 `0x67`。
- `recmod` 是“主动解析”系统变量；资料中心明确说明可配置，若不使用该模式可忽略。普通 HMI 指令通信与上述控件事件方案即可满足本项目需求。

## 4. UI 工程相关

- 分辨率：**480×272**。
- 可用控件包含：文本、滚动文本、数字、虚拟浮点、按钮、进度条、图片、切图、热区、触摸捕捉、仪表、**曲线波形**、滑块、定时器、变量、双态按钮、复选框、单选框、二维码、开关、下拉框、数据记录、文件浏览、动画、视频、音频等。

### 4.1 曲线波形控件

- **支持。**使用 `add objid,ch,val` 向当前页面的曲线控件逐点写入。
- `objid` 必须是控件 ID，推荐 `s0.id`；`ch` 范围 0–3；`val` 是 8 位数据 0–255。数值超过波形控件实际高度的部分不会显示。
- 每页最多 4 个曲线控件，每个控件最多 4 个通道；连续添加时自动左移/平推显示。资料未给出“总缓存点数”的固定值，显示宽度决定同时可见点数，不能把它当作大容量采样缓存。
- 清屏可用 `cle objid,ch`（详细参数以 `cle` 指令页为准）。为减少 3 字节帧尾造成的带宽开销，高速数据应使用 `addt` 曲线数据透传指令。

### 4.2 `addt` 透传协议（高速波形必备）

`addt objid,ch,qty`：向曲线控件批量透传数据，比逐点 `add` 高效得多。

**协议流程：**
```
MCU 发送:  addt s0.id,0,100\xff\xff\xff    ← 请求透传 100 点
等待屏返回: FE FF FF FF                     ← 透传就绪（约 5ms）
MCU 发送:  100 字节纯二进制数据（无结束符！）
屏返回:    FD FF FF FF                     ← 透传完成，曲线立即刷新
```

**关键约束：**
- 单次最大 **1024 字节**
- 透传期间发送**纯 hex 数据**，不加 `0xFF 0xFF 0xFF` 结尾
- **必须等 `0xFE` 就绪信号**再发数据，不能用固定 delay 替代
- 透传完成前曲线不刷新，完成后立即刷新
- 数据仍为 8-bit (0~255)

**性能对比（115200 baud）：**
| 方式 | 每点开销 | 100 点耗时 | 适用场景 |
| --- | --- | --- | --- |
| `add`（逐点） | ~20 字节（命令+结束符） | ~17ms | 低速实时推送 |
| `addt`（批量） | 1 字节（纯数据） | ~9ms（含握手） | 高速波形刷新 |

### 4.3 波形数据映射

ADC 为 12-bit (0~4095)，波形控件为 8-bit (0~255)，MCU 侧须映射：
```c
uint8_t wave_val = (uint8_t)(adc_raw * 255 / 4095);
```
且波形控件实际高度可能小于 255 像素，超出部分不显示。

### 4.4 波特率对波形性能的影响

| 波特率 | `add` 逐点速率 | `addt` 100 点 | 建议 |
| --- | --- | --- | --- |
| 9600 | ~48 点/秒 | ~113ms | 仅联通验证，波形卡顿 |
| 115200 | ~576 点/秒 | ~9ms | 推荐，满足实时波形 |

建议 9600 验证通信后立即切到 115200。

### 4.5 中文字库

- 工程含中文或所选字体未覆盖所需字符时，需在 USART HMI 中导入/生成相应字库，并将文本控件指向该字库。
- 通信端字符串编码必须与工程字库/工程编码一致；不要默认 UTF-8 或 GB2312 一定可直接互通，先用“中/英文混合”实测确认。

## 5. 与 MSPM0G3519 主板的对接方案

### 推荐接线

```text
5V 独立供电 ──────────────────────→ TJC VCC
J4 Pin2 GND ─────────────────────→ TJC GND（与供电 GND 共地）
MCU PC6 / UART3 TX (J4 Pin4) ───→ TJC RX
TJC TX ─────────────────────────→ MCU PC7 / UART3 RX (J4 Pin3)
```

> ⚠️ J4 Pin1 (5V) 带载不足，TJC 屏必须从其他 5V 接口独立供电。

### 实施要点

1. 不使用 UART0（PC 调试）；TJC 屏使用 UART3 (J4)，K230 可用 UART6 (J11)。
2. J4 Pin1 (5V) 带载不足，TJC 屏需从其他 5V 接口独立供电，J4 只走数据线和 GND。
3. MCU 侧已配置 115200 8N1；若无回应，确认 TJC 屏 HMI 工程的 `bauds=115200`，并确认接线交叉、共地、TX→RX 电平转换。
4. MCU 串口 RX 采用中断 + 环形缓冲区；按上述帧表解析，不要依赖一次 UART 接收回调即得到完整帧。
5. 页面按钮勾选“发送键值”；曲线控件 ID 固化后使用 `s0.id`，降低编辑 UI 后 ID 变化的风险。

## 已由 PDF 确认的硬件结论

- 原理图确认 J4 的 Pin1、Pin2、Pin3、Pin4 分别为 5V 电源、GND、`UART3-RX` (PC7)、`UART3-TX` (PC6)。
- TI 数据手册确认 `PC6` 可复用为 `UART3_TX`、`PC7` 可复用为 `UART3_RX`；二者均为普通 SDIO。
- MSPM0G3519 仅 `PA0`、`PA1` 是 5 V 容限开漏 IO。PC7 的普通 I/O 输入绝对最大额定值为 `VDD + 0.3 V`（最高不超过 4.1 V），理论上不能直接接收约 5 V 的屏 TX，但实测直连可正常通信。
- J4 Pin1 (5V) 经肖特基二极管隔离，空载约 4.7V，但带载压降过大无法驱动 TJC 屏。TJC 屏需从其他 5V 接口独立供电。

## 6. 最小验证工程教程（USART HMI）

> 目标：用 2 页工程掌握 TJC 屏全部核心交互技能，为比赛快速搭建 UI 打基础。
> 工程路径：`signal/TJC4827X543_011/TJC4827X543.HMI`
> 屏幕：480×272，编码 GB2312

### 第一步：清理出厂工程

1. 用 USART HMI 打开 `TJC4827X543.HMI`
2. 右侧页面列表中，**逐个右键删除**所有出厂页面（star, null, main, main2...）
3. 删完后页面列表应为空

### 第二步：配置字库

1. 工具栏 → **字库** → 生成字库
2. 创建 **fs0**：选 ASCII，字号 **16×32**（大号数值显示用），生成并添加
3. 创建 **fs1**：选 ASCII，字号 **8×16**（常规标签用），生成并添加

> 字库文件会自动保存在工程目录中。若字库工具入口不同版本位置有差异，在菜单栏/工具栏中查找"字库生成器"或"Font"。

### 第三步：修改 Program.s

1. 左下角点击 **Program.s**
2. 替换内容为：

```text
int sys0=0,sys1=0,sys2=0
bauds=115200
printh 00 00 00 ff ff ff 88 ff ff ff
page 0
```

> `bauds=115200` 匹配 MCU 侧 `tsp_tjc_init(115200)` 波特率，满足波形实时刷新需求。

### 第四步：创建 Page 0 — 菜单页

1. 页面列表区 → 右键 → **添加**，页面名称改为 `menu`，背景色 **bco = 0**（黑色）
2. 添加标题文本 **t0**：x=140, y=50, w=200, h=32, txt="Signal 2026", font=fs0, pco=65535(白), bco=1275(蓝)
3. 添加按钮 **b0** "Test Wave"：x=140, y=110, w=200, h=40, font=fs1, pco=65535, bco=33808(深灰)；**勾选"发送键值"**；按下事件写 `page 1`
4. 添加按钮 **b1** "Test2"（预留）：x=140, y=160, w=200, h=40；勾选"发送键值"，按下事件暂不写
5. 添加状态文本 **t1**：x=0, y=256, w=480, h=16, txt="Ready", font=fs1, pco=33808, bco=0

### 第五步：创建 Page 1 — 功能验证页

1. 新建页面 `test`，背景色 bco = 0
2. 标题文本 **t_title**：x=0, y=0, w=480, h=24, txt="Test Page", font=fs1, pco=65535, bco=16(深蓝)
3. **曲线控件 s0**（核心）：x=10, y=28, w=340, h=160, pco0=2047(青), bco=0, gdw=40, gdh=40, gdc=33808(灰)

> 曲线控件接收 0~255 的 8-bit 数据，超出控件高度的部分不显示。

4. **数字框 n0**：x=360, y=30, w=110, h=30, val=0, font=fs0, pco=2016(绿), bco=0
5. **文本框 t0**：x=360, y=70, w=110, h=20, txt="--", font=fs1, pco=65504(黄), bco=0
6. 标签 **t_n_label**（"Value: "，x=360, y=16）与 **t_t_label**（"Text: "，x=360, y=56）：font=fs1, pco=33808, bco=0
7. **Back 按钮 b_back**：x=400, y=216, w=70, h=36, txt="Back", font=fs1, pco=65535, bco=33808；勾选"发送键值"，按下事件写 `page 0`

### 第六步：编译下载

1. USART HMI 菜单 → **编译**（或工具栏编译按钮），确认无报错
2. 用 USB-TTL 连接屏幕串口，点击 **下载**，等待完成
3. 下载完成后屏幕自动重启，显示 Page 0 菜单页

### 第七步：SSCOM 验证（5 项核心技能）

下载完成后，用 USB-TTL 连接屏幕，打开 SSCOM，设置 **115200, 8N1**。勾选 **HEX 显示**（方便看返回帧），发送模式用**文本发送**。

> 提示：SSCOM 文本模式下 `\xff` 会自动转为 0xFF 字节。

**验证 1 — 按钮事件接收**：触摸 "Test Wave" → 收到 `65 00 01 01 FF FF FF`（65=控件事件帧头, 00=page_id, 01=component_id, 01=按下）。同时屏幕跳转 Page 1（按下事件 `page 1`）。component_id 取决于控件实际 ID，以收到为准。

**验证 2 — 页面跳转**：发送 `page 1\xff\xff\xff` → 屏幕跳转 Test Page；再发 `page 0\xff\xff\xff` → 返回菜单页。

**验证 3 — 更新数字框**：跳转 Page 1 后发送 `n0.val=1234\xff\xff\xff` → 显示 `1234`；再发 `n0.val=9999` → 显示 `9999`。

**验证 4 — 更新文本框**：发送 `t0.txt="Hello"\xff\xff\xff` → 显示 `Hello`；再发 `t0.txt="VIN1 OK"` → 显示 `VIN1 OK`。

**验证 5 — 波形批量透传 (addt)**（最关键的技能，分 3 步）：
1. 文本模式发送 `addt s0.id,0,10\xff\xff\xff`（先用 10 点测试）
2. 等待就绪信号 `FE FF FF FF`
3. 切 **HEX 发送模式**发送 10 字节纯数据（**不加 FF FF FF 结尾！**）：`14 28 3C 50 64 78 8C A0 B4 C8`（十进制 20~200，曲线上画出一段上升斜线）

预期：收到 `FD FF FF FF`（透传完成），曲线出现上升斜线。

## 7. 颜色速查（565 格式）
